## 🔍 АНАЛИЗ МОБИЛЬНОГО ДАШБОРДА

### Структура дашборда

**Файл:** `static/mobile-dashboard.html` (990 строк)

#### ✅ Сильные стороны:

1. **Дизайн:**
   - ✅ Liquid Glass эффект (backdrop-filter, blur)
   - ✅ Адаптивная верстка (max-width: 500px)
   - ✅ Traffic Light система стабилизации (красный/желтый/зеленый)
   - ✅ Прогресс-бар стабилизации
   - ✅ Балансировщик веса
   - ✅ Рекомендации пользователю

2. **Функциональность:**
   - ✅ Real-time обновление (setInterval 1000ms)
   - ✅ Авто/Ручной режим переключения
   - ✅ Ручная фиксация акта
   - ✅ Экспорт в Excel
   - ✅ Сверка с Excel
   - ✅ История стабилизации (30 последних измерений)

3. **UX:**
   - ✅ Визуальная индикация состояния
   - ✅ Анимации и переходы
   - ✅ Обработка ошибок (try-catch)
   - ✅ Состояния загрузки (disabled кнопок)

#### ❌ Проблемы и ограничения:

1. **Жестко заданный API_URL:**
   ```javascript
   const API_URL = 'http://localhost:8000/api';
   ```
   - ❌ Не работает на других хостах/портах
   - ❌ Не работает при HTTPS
   - ⚠️ Решение: использовать относительные пути или `window.location.origin`

2. **Отсутствие обработки ошибок сети:**
   - ❌ Нет retry при сбоях сети
   - ❌ Нет индикации потери связи
   - ⚠️ Решение: добавить exponential backoff и индикатор связи

3. **Формат ответа API не соответствует ожиданиям:**
   - ❌ Дашборд ожидает `data.metrics.recall`, но API может вернуть другую структуру
   - ⚠️ Решение: проверить формат ответа `compare_excel.py`

4. **Нет обработки CORS:**
   - ❌ Если дашборд открыт с другого домена, будут ошибки CORS
   - ⚠️ Решение: настроить CORS в FastAPI (уже есть в middleware)

5. **Экспорт Excel:**
   - ⚠️ Дашборд отправляет JSON body, но `export.py` ожидает Query параметры
   - ❌ Конфликт между `export_excel.py` (Body) и `export.py` (Query)
   - ⚠️ Решение: использовать только `export_excel.py` с Body

## 🔌 ИНТЕГРАЦИЯ С API

### Endpoints, используемые дашбордом:

| Endpoint | Метод | Статус | Проблемы |
|----------|-------|--------|----------|
| `/api/stats/current` | GET | ✅ Работает | Нет |
| `/api/metrics/toggle-auto-fix` | POST | ✅ Работает | Работает только со STREAM_MANAGER (runtime) |
| `/api/metrics/manual-fix` | POST | ✅ Работает | Работает только со STREAM_MANAGER (runtime) |
| `/api/export/excel` | POST | ⚠️ Конфликт | Два endpoint с разными форматами |
| `/api/compare/excel` | POST | ✅ Работает | Формат ответа может не совпадать |

### Проблемы интеграции:

1. **Дублирование `/api/export/excel`:**
   - `api/endpoints/export_excel.py` - POST с Body (правильный)
   - `api/endpoints/export.py` - POST с Query (неправильный для дашборда)
   - ⚠️ Решение: удалить `/api/export/excel` из `export.py` или использовать другой путь

2. **Формат ответа `/api/compare/excel`:**
   - Дашборд ожидает: `{ matches, discrepancies, accuracy, metrics: { recall, precision, f1_score }, report_url }`
   - API возвращает: `{ matches, discrepancies, missing_in_auto, missing_in_manual, accuracy, metrics, report_url }`
   - ✅ Формат соответствует ожиданиям дашборда

3. **Статистика из БД:**
   - `get_stats_summary()` возвращает словари, не объекты
   - ✅ Исправлено в `stats.py` (используется `.get()`)

## 🚨 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. Дублирование endpoints

**Проблема:** Два endpoint `/api/export/excel` с разными форматами запроса

**Файлы:**
- `api/endpoints/export_excel.py` - POST с Body (правильный)
- `api/endpoints/export.py` - POST с Query (неправильный)

**Решение:**
- Удалить `/api/export/excel` из `export.py`
- Оставить только `export_excel.py`

### 2. Жестко заданный API_URL

**Проблема:** `const API_URL = 'http://localhost:8000/api';`

**Решение:**
```javascript
const API_URL = `${window.location.origin}/api`;
```

### 3. Отсутствие обработки ошибок сети

**Проблема:** Нет retry и индикации потери связи

**Решение:**
- Добавить exponential backoff
- Добавить индикатор связи (онлайн/оффлайн)
- Добавить очередь запросов при потере связи

### 4. Формат ответа compare_excel

**Проблема:** Возможны различия в структуре ответа

**Решение:**
- Проверить формат ответа `ExcelComparator.compare()`
- Убедиться, что `comparison.get("metrics", {})` возвращает правильную структуру
