# Исправление проблем с RTSP потоками

## Проблемы после устранения спама

После устранения спама в логах стали видны реальные проблемы:

### 1. ❌ Ошибка 10054 (WSAECONNRESET)
```
Error number -10054 occurred: 'rtsp://...'
```
**Причина:** Камера разрывает RTSP соединение (сетевые проблемы, перегрузка камеры, таймаут)

### 2. ⏱️ Таймауты чтения кадров
```
av_worker timeout on read_jpeg after 2.0s
```
**Причина:** Worker не успевает прочитать кадр за 2 секунды (медленная сеть, перегрузка)

### 3. ⏱️ Таймаут закрытия потока
```
av_worker timeout on close after 15.1s
```
**Причина:** Worker зависает при закрытии RTSP потока

## Исправления

### 1. Увеличены таймауты
- `read_jpeg`: 1.0s → 3.0s (для медленных RTSP потоков)
- `close`: 15.0s → 5.0s (быстрое закрытие, не ждём зависший поток)

### 2. Улучшено логирование
- Таймауты чтения кадров: ERROR → DEBUG (не засоряют логи)
- Таймауты закрытия: ERROR → WARNING
- Ошибка 10054: логируется раз в 10 секунд (не спамит)

### 3. Добавлена обработка разрыва соединения
- Ошибка 10054 обрабатывается корректно
- Логируется предупреждение о необходимости переподключения
- Не спамит логи (раз в 10 секунд на поток)

## Код изменений

### Увеличен таймаут чтения
```python
def read_jpeg(self, sid: str, timeout: float = 3.0):  # было 1.0
    """Читает JPEG кадр из потока. Увеличен таймаут для RTSP."""
```

### Умное логирование таймаутов
```python
if cmd in ['read_jpeg', 'seek_read_jpeg']:
    logger.debug(f"av_worker timeout on {cmd} (worker busy)")
elif cmd == 'close':
    logger.warning(f"av_worker timeout on {cmd}")
else:
    logger.error(f"av_worker timeout on {cmd}")
```

### Обработка ошибки 10054
```python
if "10054" in error_msg or "Connection reset" in error_msg:
    if current_time - last_log > 10.0:  # Раз в 10 секунд
        logger.warning(f"⚠️ RTSP соединение разорвано камерой {sid}")
```

### Быстрое закрытие потока
```python
def close(self, sid: str) -> None:
    try:
        self._req('close', {'id': sid}, timeout=5.0)  # было 15.0
    except TimeoutError:
        logger.warning(f"Timeout closing {sid}, forcing cleanup")
```

## Рекомендации

### Если камера часто разрывает соединение:

1. **Проверьте сеть:**
   ```bash
   ping -t 10.15.6.27
   ```

2. **Проверьте настройки камеры:**
   - Увеличьте таймаут keep-alive
   - Проверьте максимальное количество подключений
   - Проверьте настройки RTSP сервера

3. **Попробуйте UDP транспорт:**
   Система автоматически пробует UDP если TCP не работает

4. **Снизьте нагрузку:**
   - Уменьшите FPS (уже 20)
   - Уменьшите разрешение потока на камере
   - Проверьте битрейт потока

### Если таймауты чтения продолжаются:

1. **Проверьте сетевую задержку:**
   ```bash
   ping -n 100 10.15.6.27
   ```
   Должна быть < 50ms

2. **Проверьте пропускную способность:**
   - RTSP поток обычно требует 2-8 Mbps
   - Проверьте загрузку сети

3. **Увеличьте таймаут вручную:**
   В коде можно увеличить с 3.0 до 5.0 секунд

### Автоматическое переподключение

Система должна автоматически переподключаться при разрыве соединения.
Если этого не происходит, проверьте логи на наличие:
```
✅ RTSP подключение успешно: cam101
```

## Мониторинг

Следите за логами на наличие:
- ⚠️ Предупреждений о разрыве соединения (не чаще раза в 10 секунд)
- ⚠️ Таймаутов закрытия (не должно быть часто)
- ✅ Успешных переподключений

Если проблемы сохраняются > 5 минут, перезапустите поток вручную через UI.
