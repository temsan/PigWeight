# Отчет о реализации фоновой системы событий

## Выполненные задачи

### ✅ Критичная задача 7.1: Журналирование ключевых событий

Полностью реализована система фонового журналирования событий для PigWeight:

## 🔧 Бэкенд компоненты

### 1. EventLogger Service (`services/event_logger.py`)
- **Функциональность**: Основной сервис для записи и управления событиями
- **Возможности**:
  - Автоматическое сохранение кадров при важных событиях
  - Детекция всплесков активности (рост > N свиней за M секунд)
  - Отслеживание пиковых значений количества
  - Журналирование пересечений линий детекции
  - Автоматическая очистка старых событий
  - Хранение в JSONL формате для эффективности

### 2. Интеграция с UnifiedVideoProcessor (`core/processor.py`)
- **Обновления**:
  - Добавлена интеграция с системой событий
  - Автоматическая обработка событий при каждом кадре
  - Упрощенная детекция пересечения линий
  - Отслеживание пиков и всплесков в реальном времени
  - Cooldown система для предотвращения спама событий

### 3. API Endpoints (`api/endpoints/events.py`)
- **Новые маршруты**:
  - `GET /api/events/streams` - список активных потоков
  - `GET /api/events/{stream_id}` - события с фильтрацией
  - `GET /api/events/{stream_id}/stats` - статистика по потоку
  - `GET /api/events/{stream_id}/frame/{event_id}` - кадры событий
  - `GET /api/events/{stream_id}/export` - экспорт в CSV/JSON
  - `POST /api/events/{stream_id}/cleanup` - ручная очистка
  - `DELETE /api/events/{stream_id}` - удаление всех событий

### 4. Фоновые задачи (`api/app.py`)
- **Автоматизация**:
  - Фоновая задача очистки старых событий (каждый час)
  - Graceful shutdown с корректной остановкой задач
  - Обработка ошибок и логирование

## 📊 Типы отслеживаемых событий

### 1. 🚶 Пересечения линий (line_crossing)
- Детекция объектов в зоне между линиями
- Сохранение кадра с позициями объектов
- Метаданные: координаты центроидов, позиции линий

### 2. 📈 Пики количества (peak_count)
- Автоматическое обновление максимального значения
- Сохранение кадра при достижении нового пика
- Метаданные: предыдущий пик, текущие координаты

### 3. ⚡ Всплески активности (activity_spike)
- Детекция резкого роста количества за короткое время
- Настраиваемые пороги (по умолчанию: +5 свиней за 10 сек)
- Метаданные: предыдущее количество, динамика изменений

## 🗂️ Структура хранения данных

### Файловая система
```
records/
├── events/
│   └── {stream_id}_events.jsonl  # События в JSONL
└── frames/
    └── evt_{timestamp}_{id}.jpg  # Кадры событий
```

### Формат события
```json
{
  "event_id": "evt_1727172000000_000001",
  "stream_id": "camera_01", 
  "event_type": "peak_count",
  "timestamp": 1727172000.123,
  "pig_count": 15,
  "confidence": 0.85,
  "frame_path": "records/frames/evt_1727172000000_000001.jpg",
  "metadata": {...}
}
```

## ⚙️ Настройки и конфигурация

### Параметры событий
- `event_cooldown = 2.0` - минимальный интервал между событиями
- `spike_threshold = 5` - порог для всплесков активности  
- `spike_window_sec = 10.0` - временное окно для всплесков
- `max_events_per_stream = 1000` - лимит событий в памяти

### Автоматическая очистка
- Очистка событий старше 24 часов каждый час
- Удаление связанных файлов кадров
- Логирование операций очистки
