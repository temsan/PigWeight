### 2. ✅ Задача 15: Миграция API на DatabaseManager

**Проблема:**
`api/endpoints/metrics.py` использовал `STREAM_MANAGER` (in-memory) вместо `DatabaseManager` (PostgreSQL/Supabase).

**Решение:**

#### 2.1 Обновлён `api/endpoints/metrics.py`
- Импортирован `get_database_manager()` из dependencies
- Обновлён endpoint `/api/metrics/current`:
  - Получение данных из БД через `DatabaseManager.get_stats_summary()`
  - Graceful degradation при недоступности БД
  - Сохранена поддержка real-time данных из STREAM_MANAGER
  - Улучшенная обработка ошибок

#### 2.2 Обновлён `pig_tracking/database_manager.py`
- Добавлен параметр `stream_id` в метод `get_stats_summary()`
- Добавлены поля `total_pigs`, `total_weight`, `avg_weight` в ответ
- Улучшено логирование

#### 2.3 Созданы новые стандартизированные endpoints
- `GET /api/stats/current` - стандартизированное название (переиспользует логику `/api/metrics/current`)
- `GET /api/health` - проверка состояния системы (БД, STREAM_MANAGER)
- `GET /api/weighing/acts` - список актов с пагинацией и фильтрами
- `GET /api/weighing/stats` - агрегированная статистика

**Результат:**
- ✅ API теперь использует PostgreSQL/Supabase вместо in-memory
- ✅ Обратная совместимость сохранена
- ✅ Graceful degradation при недоступности БД
- ✅ Соответствие спецификации design.md

**Файлы:**
- `api/endpoints/metrics.py` - обновлён (+200 строк)
- `pig_tracking/database_manager.py` - обновлён метод get_stats_summary()

### 3. ✅ Задача 16: Усиление проверки инициализации DatabaseManager

**Проблема:**
В `api/app.py` инициализация DatabaseManager была обёрнута в try/except без явного сбоя, создавая риск silent failure.

**Решение:**

#### 3.1 Обновлён блок инициализации в `api/app.py`
- Добавлена переменная окружения `DB_REQUIRED` (default: true)
- Добавлена проверка подключения через `db_manager.test_connection()`
- Два режима работы:
  - **DB_REQUIRED=true** (по умолчанию): останавливает приложение при ошибке БД
  - **DB_REQUIRED=false**: продолжает работу с предупреждением

#### 3.2 Улучшенное логирование
- ✅ Успешное подключение: `✅ DatabaseManager инициализирован и подключен к БД`
- ❌ Критическая ошибка: `❌ КРИТИЧЕСКАЯ ОШИБКА: ...` + инструкции по исправлению
- ⚠️ Предупреждение: `⚠️ Приложение продолжит работу без базы данных`

**Результат:**
- ✅ Нет риска silent failure
- ✅ Явное указание критичности БД
- ✅ Понятные сообщения об ошибках
- ✅ Гибкость конфигурации (DB_REQUIRED)

**Файлы:**
- `api/app.py` - обновлён блок инициализации DatabaseManager
