# Руководство по системе событий PigWeight

## Обзор

Система событий PigWeight автоматически отслеживает и записывает ключевые события в видеопотоке:

- 🚶 **Пересечения линий** - когда объекты пересекают зоны детекции
- 📈 **Пики количества** - новые максимальные значения количества свиней
- ⚡ **Всплески активности** - резкий рост количества за короткое время

## Архитектура

### Бэкенд компоненты

1. **EventLogger** (`services/event_logger.py`)
   - Основной сервис для журналирования событий
   - Сохраняет события в JSONL файлы
   - Автоматически сохраняет кадры для важных событий
   - Поддерживает автоматическую очистку старых данных

2. **UnifiedVideoProcessor** (обновлен)
   - Интегрирован с системой событий
   - Автоматически детектирует события при обработке кадров
   - Вызывает соответствующие методы EventLogger

3. **API Endpoints** (`api/endpoints/events.py`)
   - `/api/events/streams` - список активных потоков
   - `/api/events/{stream_id}` - события для потока
   - `/api/events/{stream_id}/stats` - статистика по потоку
   - `/api/events/{stream_id}/frame/{event_id}` - кадр события
   - `/api/events/{stream_id}/export` - экспорт событий

### Фронтенд компоненты

1. **EventsManager** (`static/js/events-manager.js`)
   - Управляет отображением событий в интерфейсе
   - Автоматическое обновление каждые 5 секунд
   - Фильтрация по типу и времени
   - Экспорт в CSV

2. **Панель События** (в `static/index.html`)
   - Новая вкладка "События" в интерфейсе
   - Статистика по событиям
   - Список событий с возможностью просмотра кадров

## Использование

### Просмотр событий

1. Откройте веб-интерфейс PigWeight
2. Выберите активный поток видео
3. Перейдите на вкладку "События" 🎯
4. События будут автоматически загружены и отображены

### Фильтрация событий

- **По типу**: выберите тип события в выпадающем списке
- **По времени**: выберите временной диапазон (1 час, 6 часов, 24 часа)
- Нажмите 🔄 для ручного обновления

### Просмотр кадров

- Нажмите кнопку "🖼️ Показать кадр" рядом с событием
- Кадр откроется в модальном окне
- Кликните вне кадра или на ❌ для закрытия

### Экспорт данных

- Нажмите кнопку 📥 для экспорта событий в CSV
- Файл будет автоматически скачан
- Экспорт учитывает текущие фильтры

## Настройка

### Параметры событий

В `core/processor.py` можно настроить:

```python
# Минимальный интервал между событиями (секунды)
self.event_cooldown = 2.0

# Позиции линий детекции (0.0 - 1.0)
self.line_left_x = 0.25
self.line_right_x = 0.75
```

В `services/event_logger.py`:

```python
# Порог для всплесков активности
spike_threshold = 5  # количество свиней

# Временное окно для всплесков
spike_window_sec = 10.0  # секунд

# Максимальное количество событий в памяти
max_events_per_stream = 1000
```

### Автоматическая очистка

Система автоматически очищает события старше 24 часов каждый час.
Настройка в `api/app.py`:

```python
await event_logger.cleanup_old_events(max_age_hours=24)
```

## Хранение данных

### Структура файлов

```
records/
├── events/
│   └── {stream_id}_events.jsonl  # События в JSONL формате
└── frames/
    └── evt_{timestamp}_{id}.jpg  # Кадры событий
```

### Формат события

```json
{
  "event_id": "evt_1727172000000_000001",
  "stream_id": "camera_01",
  "event_type": "peak_count",
  "timestamp": 1727172000.123,
  "pig_count": 15,
  "confidence": 0.85,
  "frame_path": "records/frames/evt_1727172000000_000001.jpg",
  "metadata": {
    "previous_peak": 12,
    "centroids": [[0.3, 0.4], [0.6, 0.7]]
  }
}
```

## API Примеры

### Получение событий

```bash
# Все события потока
curl "http://localhost:8000/api/events/camera_01"

# События за последний час
curl "http://localhost:8000/api/events/camera_01?since_hours=1"

# Только пересечения линий
curl "http://localhost:8000/api/events/camera_01?event_type=line_crossing"
```

### Статистика

```bash
curl "http://localhost:8000/api/events/camera_01/stats"
```

### Экспорт

```bash
# CSV экспорт
curl "http://localhost:8000/api/events/camera_01/export?format=csv" -o events.csv

# JSON экспорт
curl "http://localhost:8000/api/events/camera_01/export?format=json"
```

## Мониторинг

### Логи

События записываются в лог с уровнем INFO:

```
2025-09-24 13:08:15 - services.event_logger - INFO - Peak count logged: stream=camera_01, new_peak=15, previous=12
2025-09-24 13:08:20 - services.event_logger - INFO - Line crossing logged: stream=camera_01, count=8, confidence=0.82
```

### Производительность

- События обрабатываются асинхронно
- Сохранение кадров происходит в фоне
- Автоматическая очистка не блокирует основной поток

## Устранение неполадок

### События не записываются

1. Проверьте, что поток активен и обрабатывается
2. Убедитесь, что директории `records/events` и `records/frames` существуют
3. Проверьте логи на ошибки импорта `services.event_logger`

### Кадры не отображаются

1. Проверьте права доступа к директории `records/frames`
2. Убедитесь, что OpenCV корректно сохраняет изображения
3. Проверьте доступность файлов через API

### Высокое потребление памяти

1. Уменьшите `max_events_per_stream`
2. Сократите интервал автоматической очистки
3. Настройте более агрессивную очистку старых кадров

## Расширение функциональности

### Добавление новых типов событий

1. Добавьте новый тип в `EventLogger`
2. Реализуйте логику детекции в `UnifiedVideoProcessor`
3. Обновите фронтенд для отображения нового типа

### Интеграция с внешними системами

События можно отправлять в:
- Базы данных (PostgreSQL, MongoDB)
- Системы мониторинга (Prometheus, Grafana)
- Уведомления (Telegram, Email, Slack)

Для этого расширьте класс `EventLogger` соответствующими методами.
